## 顺序步骤

1. 以 T09 bodies 和 bodyConditions 作为参考预期，不直接当已审核结果加载；实现统一摘要、银行稿、电信稿的生成、编辑和版本依赖。无指引只生成事实摘要。
2. 内容重算保留员工修改，给出差异待确认，不静默覆盖。拒绝建议从相关待执行内容移除，保留事实与拒绝记录；接收方来自有效配置。
3. 实现仅首次核对和最终审核两个阶段；最终审核按对象与依赖绑定；选定摘要／草稿引用的建议也须具有当前有效的最终审核，不能只检查正文对象。事实／分类／权限／指引／引用建议变化只使依赖对象失效；重复相同分析和纯排版不使审核失效。
4. 服务端重新构建并验证运行快照后输出；复制、Markdown、PDF 共用固定正文。阻止未保存、待确认变化、无审核或过期审核导出，输出失败保留审核与预览可原版本重试。
5. 提供已保存且已审核的运行快照固定构造方法与 tests/outputs.test.ts；记录生成方式给 A06，E02通过A06页面操作，禁止伪造审核人／已送达状态。运行核心、服务、构建和浏览器检查。

共享结构变化后执行 `npm run schemas`，核对data/schemas生成差异与本卡契约同步；只交实际受影响文件。未改结构不为刷新时间戳重写生成物。

人工修改采用PRD 4.4的轻量规则：保留原内容及Employee edited标记，修改后重新审核；不自行新增语义审查、自动风险评分或人工文字逐句指引拦截。系统生成建议仍遵守既有匹配规则。

## 固定检查与预期

| 输入／操作 | 应观察到的结果 |
|---|---|
| 修改银行稿或其接收方 | 银行稿需重审；无依赖变化的电信稿保持有效 |
| 事实／指引变化及拒绝建议 | 受影响对象审核失效，拒绝动作不作为待执行项复活 |
| 无指引最终审核 | 只核对事实摘要，不要求不存在的建议或接收方 |
| 复制／MD／PDF／失败重试 | 相同正文、案件号及版本；过期与未保存均阻断，失败不改源内容 |

命令从本副本项目根目录执行；Windows使用npm.cmd，macOS使用npm。只执行本卡步骤要求的检查；需要浏览器时先构建并安装Chromium。前置新建命令由A实际验证后填工作包，成员不猜命令。
