# 团队执行规则

A负责规则确认、公共技术基础、技术审核和集成。B–F使用固定输入和指定文件完成限定工作，不要求成员自行设计架构或产品规则。两台Windows、四台macOS；实际成员映射后续人工确认，见[TEAM](TEAM.md)。采用文件交A，不要求截止时间。

## 责任与实际起点

| 方向 | 责任 | 当前任务 |
|---|---|---|
| A | 产品决定、公共逻辑、完整最小界面及事件绑定、技术检查、案例准备、集成及交付 | A01–A08 |
| B | 在已接通页面上调整指定事实／分析展示，不承担工作流接入 | B01、B02 |
| C | 提示内容、固定输入的分析效果核对 | C01、C02 |
| D | 岗位权限、指引和参考预期的内容核对 | D01、D02 |
| E | 同一快照的预览与复制／双格式排版 | E01、E02 |
| F | 两系统运行、固定案例验收、缺陷及复测 | F01–F03 |

统一方案、运行骨架、共享模拟数据和有限T09批准包已有实际文件；完整运行工作流仍待开发。已验证范围见[STATUS](STATUS.md)及[就绪盘点](FOUNDATION_READINESS.md)，操作见[RUNBOOK](../architecture/RUNBOOK.md)。

A先确定产品规则和可观察预期，再实现公共功能及能直接操作的最小页面。成员只在已填起点上修改或观察；控制器签名、空组件、架构说明不能代替可运行起点。F按独立步骤检查，不能把A的作者自检当成F执行。

## 领取和开工

1. 从[TASKS](TASKS.md)选择由A指派的一张卡；每次只推进一个主任务，A也按依赖串行整合共享文件。
2. 核对成员、实际工作副本、允许文件和全部开工条件。A按[工作包清单](WORK_PACKAGE.md)填写副本编号、基线、输入、目标和操作记录，交付完整本地项目。成员电脑不复制node_modules、.env或local。
3. 读取AGENTS、STATUS、该卡及其指定资料。依赖产物未验收、文件缺失或工作区有未交接改动，保留现场，记录具体缺项交A。
4. 按顺序步骤修改和检查。B–F不得扩大共享结构、模型权限、业务规则或验收标准；需要时交A决定并更新对应卡范围。
5. 成员亲自核对可观察结果，模拟、真实模型、内容审核、程序验证和未执行项分别记录。文件生成或agent声称通过不等于验收。

## 任务说明与执行记录

任务卡维护目标、输入、允许文件、步骤和预期。尚无对应Issue时，实际成员、状态、检查和证据只记录在卡内“唯一执行记录”；TASKS只索引依赖，STATUS由A汇总集成结果。

若A明确建立对应Issue，将当时实际成员、状态和结果转入Issue，卡内改为该Issue链接；说明继续留卡内，不重复维护动态结果。仓库存在不等于已经有对应Issue。

状态为待指派→进行中→待审核→已验收。阻塞注明具体依赖、影响和需要谁提供什么；待指派不表示可以立即开工。不得把前置基座的通过记录继承为新卡已验收。已验收任务后续需修复时，A在同一唯一记录追加修复批次并转进行中，保留原验收和失败记录，重新检查受影响依赖；不复制新状态到另一份表。检查报告卡C02／F02／F03的验收是报告真实完整，报告可包含产品失败；产品是否可交付另依F03结论和A08门槛判断，避免等待修复才能提交首轮缺陷报告。

## 文件交付与共同文件

按卡片允许范围交文件清单、差异和证据给A；不自动暂存、提交、推送、创建PR、部署或对外发送。成员不把整份改过的项目覆盖A工作副本。A逐项审查和集成允许差异；冲突由A处理，不自动采用某一方全部内容。

B01先完成并经A集成，再向E01发放新副本；E01完成后A04接入输出逻辑。A06由A接通完整最小界面、审核操作和故障入口，之后E02核对运行输出，再由B02调整运行事实区展示。E02与B02共用CSS，严格按此顺序交接。C01先于A02修改提示；C02再次调整提示后，由A集成并把同一最终副本交F02。A01–A05共享schema／workflow等文件，由A串行推进。其他范围出现冲突先停受影响文件。

截图、脱敏日志及输出放各卡指定的evidence/task-results/编号/执行批次/；首次run-01、复测run-02，保留失败。密钥、.env、local、真实个人信息和机器缓存不交付。实际操作方法见[CONTRIBUTING](../../CONTRIBUTING.md)。

## 审核与模型使用

A审核代码、接口、数据及业务规则；成员或F核对操作和内容。A自己的实现附作者自检，由F独立执行行为检查；不得伪造另一位技术审核人。新增案例／配置须有A实际内容审阅，T09既有批准不自动覆盖新增内容。

真实API由用户在产品内自主配置并主动调用；保存配置不调用模型。agent不索要密钥、不自动进行付费调用。没有真实结果就写未执行，本地假服务不替代真实模型效果验收。

F按给定输入、步骤和预期记录缺陷；A安排原责任范围修复，F重复原步骤复测。权限、无依据事实／指引、审核失效和补问上限的关键失败不能用总体通过率抵消。

## 可复制给agent的指令

```text
按AGENTS.md、docs/project/STATUS.md和A已指派的具体任务卡执行。
先核对任务卡唯一执行记录中的成员、实际工作副本和依赖验收。
只改允许范围，保留已有工作，不提交或推送。
缺输入、接口或规则时记录具体阻塞，不自行补架构或改标准答案。
逐步执行卡内检查，区分通过、失败、未执行、mock和真实模型。
只更新该卡的唯一记录，并给出成员亲自核对的操作与证据位置。
```
