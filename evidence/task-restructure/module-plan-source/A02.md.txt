## 顺序步骤

1. 使用 A01 的运行案件结构，给自由描述、补充来源、模型提议和补问提议定义严格服务响应；模型不能提交岗位、批准、审核或任意字段。新增问题字段必须有 schema 和错误路径，不能只改提示。
2. 在公共控制器接通提取→员工更正与首次核对→补问。人工更正金额 200 优先；模型重读 2000 时留候选冲突。员工可更正疑似类型并保留依据／历史；用现有groupAmounts按币种和交易状态给出报告值汇总，要求付款不计已付款，未知金额／币种单列，不换汇、不写确认损失。只有实质变化才递增相关版本；首次核对后的直接修改需确认变化，普通回答不逐轮首次审核。
3. 问题带稳定 ID、字段＋记录目标及原因；当前轮部分处理不新开轮。只有成功展示且保存计数，失败／重试幂等，零题不计数；3轮／9题上限、未知不重复问、提前结束与后补答案都由程序控制。
4. 模型请求绑定案件、事实、角色、指引、设置和当前请求身份；较旧响应不得覆盖更正、计数或审核。超时／解析失败保留输入和已保存结果，API 设置保存仍不自动分析。
5. 导出 useWorkflow 的命令与选择器供 A06 接入界面；给 tests/workflow-browser.ts 建立可执行浏览器入口，固定有效／无效／延迟返回由本地假提供商提供，记录准确运行命令。真实调用仅用户在产品中主动执行。

共享结构变化后执行 `npm run schemas`，核对data/schemas生成差异与本卡契约同步；只交实际受影响文件。未改结构不为刷新时间戳重写生成物。

## 固定检查与预期

| 输入／操作 | 应观察到的结果 |
|---|---|
| T09：2000→员工200→重新分析原文 | 当前200，候选2000有来源；员工决定前不消除冲突 |
| 三题只答Q1，再刷新 | 仍同轮，Q2/Q3待处理；计数不重复 |
| 未知／结束／后补答案／第9题 | 不换措辞重复问，不重置计数；上限后仍能处理已展示题 |
| 生成失败／保存失败／旧响应 | 不消耗新轮次；未保存可重试，旧响应不得覆盖新状态 |

命令从本副本项目根目录执行；Windows使用npm.cmd，macOS使用npm。只执行本卡步骤要求的检查；需要浏览器时先构建并安装Chromium。前置新建命令由A实际验证后填工作包，成员不猜命令。
