## 顺序步骤

1. 用批准包 EX-G01–03 及 T09 的事实条件实现确定性匹配；逐项检查已批准、有效、岗位权限、required、allowedUnknown、onMismatch 和来源，不按类型名称直接命中。
2. 输出本岗位可做、相关接收方职责、优先级、理由、依赖与局限；部分不匹配只省略对应步骤并列原因；冲突指引保留引用，禁止模型任选一个。
3. 实现接受、修改、拒绝及理由持久化；接受不表示执行，拒绝不删除事实，重新分析不撤销决定。通知依赖该建议的对象更新，不影响无依赖对象。
4. 实现岗位／指引变更重算入口，保留事实、首次审核历史与补问计数；未提供的角色 ID 拒绝。用测试注入未批准、失效、冲突和低权限配置，不把它们注册为有效内容。
5. 无任何有效适用指引时仅允许事实摘要路径，返回固定英文提示，不生成建议／机构路径／交接草稿；建立测试及公共消费者接口。

共享结构变化后执行 `npm run schemas`，核对data/schemas生成差异与本卡契约同步；只交实际受影响文件。未改结构不为刷新时间戳重写生成物。

人工修改采用PRD 4.4的轻量规则：保留原内容及Employee edited标记，修改后重新审核；不自行新增语义审查、自动风险评分或人工文字逐句指引拦截。系统生成建议仍遵守既有匹配规则。

## 固定检查与预期

| 输入／操作 | 应观察到的结果 |
|---|---|
| T09 当前获批条件 | 每条建议引用准确指引编号／版本和事实，不宣称动作已完成 |
| 拒绝 T09 第三条建议并重算 | 理由保留；待执行摘要／草稿不得引用被拒绝动作 |
| 指引失效／冲突／岗位无权限 | 不输出对应步骤；零匹配仅摘要并显示 Insufficient approved guidance; human review required |
| 切换岗位 | 事实和题数不变；只更新受影响建议／输出依赖 |

命令从本副本项目根目录执行；Windows使用npm.cmd，macOS使用npm。只执行本卡步骤要求的检查；需要浏览器时先构建并安装Chromium。前置新建命令由A实际验证后填工作包，成员不猜命令。
