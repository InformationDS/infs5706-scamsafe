# F01：执行两系统公共基座独立运行检查

## 目标与责任

目标：执行两系统公共基座独立运行检查，只完成本卡范围。建议角色：F；实际成员由 A 人工指派。产品规则：FR-10, FR-11, FR-12，以卡内指定PRD条款为准。

## 开工条件

依赖：无开发任务依赖；使用当前已验证公共基座。

技术输入已具备；A 指派实际成员并提供完整工作副本后可开工。

A 指派时在下方唯一执行记录确认工作副本实际绝对路径；Windows 可使用当前项目目录，macOS 使用成员自己的项目根目录。没有完整文件、存在未交接改动或检查失败时保留现场，交 A 判断。不得按远端文件存在推定本地新增文件已发布。

## 允许修改与交付

现有文件：无；只核对、运行和记录，不修改程序、配置或标准答案。

本卡新建产物（当前不要求存在）：无业务／程序新文件。

检查截图、日志和脱敏输出可新建于 `evidence/task-results/F01/`。只更新本卡“唯一执行记录”；不更新其他卡状态、TASKS或STATUS（仅本卡允许范围列出时可改STATUS）。禁止将密钥、.env、local/或实际个人信息交付。

交付方式：文件交A，按[CONTRIBUTING](../../../CONTRIBUTING.md)收集允许差异、本卡和证据；不执行Git交付。

## 顺序步骤

1. A提供包含本地新增文件的完整项目副本；不从尚未更新的远端下载替代。Windows与macOS分别记录系统、Node24、npm、浏览器版本及实际项目路径，不复制node_modules／.env／local。
2. 按 RUNBOOK 安装、构建、启动，Windows用npm.cmd，macOS用npm；在5173加载partial并刷新，记录一轮三问和回答保留。
3. 下载JSON备份，在4310构建页面导入并保存，核对案件、金额、问答、计数；两个origin不应自动共享历史。先停dev再npm start避免4310冲突。
4. 在这份不带.env／local的独立工作副本中，以Mock保存一个不含真实凭证的API设置，关闭重开确认；密钥不回显、备份不含设置。不要为本卡自动调用真实服务，也不清除用户已有配置。
5. 运行 npm run check、npm run build、npm run check:browser -- evidence/task-results/F01/run-01/browser，记录真实系统下结果与PDF逐页观察；没有可用Mac就写未执行及缺什么，不照抄A的Windows结果。

## 固定检查与预期

| 输入／操作 | 应观察到的结果 |
|---|---|
| Windows和macOS各至少一台 | 均有独立安装、启动、检查及PDF观察记录；不能推定六台都通过 |
| 5173→备份→4310 | 导入保存后内容一致；未导入前不是同一浏览器存储 |
| 失败 | 有原文、步骤、系统与截图位置，不擅改端口依赖或清空存储 |

命令从本副本项目根目录执行；Windows使用npm.cmd，macOS使用npm。只执行本卡步骤要求的检查；需要浏览器时先构建并安装Chromium。前置新建命令由A实际验证后填工作包，成员不猜命令。

## 停止、审核与完成条件

缺输入、接口冲突或需要范围外修改时，保留现场并停止受影响步骤，按[AGENTS](../../../AGENTS.md)报告具体缺项；不自行补架构、改业务规则或标准答案。

成员填写实际观察，A审核技术与集成。本卡要求的交付与检查有证据、相关问题解决且A确认后才标已验收；不继承基座通过结论。

证据写evidence/task-results/F01/run-01/；复测使用run-02等新批次，保留首次失败。
