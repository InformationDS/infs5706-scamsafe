## 顺序步骤

1. 确认 suite.json 已有 A 批准的15例与答案，A06 已提供集成界面、运行分析和补问入口；先用固定假返回核对程序输入结构。
2. 真实调用由用户在产品 Configure model API 自主配置并主动发起；没有明确真实执行条件时只做静态对照，真实结果保持未执行。
3. 按 T01–T15 原文及给定答案分别记录模型标识、输入、事实来源、候选分类、缺口、题数、无依据内容与错误；不要求逐字复现参考正文。
4. 发现提示问题每次只改一处并对同例前后比较；涉及输出字段或控制规则交 A，不改 schema，不直接编辑标准答案。
5. 将漏项、捏造事实、越权、重复问和解析失败分别列出，交 A 决定提示调整或程序修复；复测受影响案例。

### 演示案例的简短操作对照

以下按钮已存在于当前基座，可用于理解T09固定输入及观察位置；不是自由输入的完整业务流程，也不替代本卡前置验收。按RUNBOOK启动，保持Mock；每行从指定状态独立加载，需要保留原案时先下载JSON备份。

| 固定输入与操作顺序 | 可见预期 |
|---|---|
| Fixed training state选intake → Load training state → 等待Loaded and saved → 展开Original report · S1–S5 → Run adapter | 原文金额2000 AUD；收到mock分析对照，显示候选类型和不确定性；不自动审核或改写案件 |
| 选corrected → Load training state → 等待保存完成 → Run adapter → 查看事实区与返回对照 | 当前金额保持200 AUD，2000原文及更正历史保留；模型返回不能自动覆盖当前更正 |
| 选no-guidance → Load training state → 等待保存完成 → Simulate final summary review → 等待保存完成 → 在Preview & output查看默认选中的事实摘要及预览 → Download Markdown | 只输出事实摘要，保留无有效指引、合成和模拟标记；不生成具体建议或接收方稿 |

实际演示真实模型时，由用户在Configure model API保存配置并主动点击Run adapter，记录真实返回；不能把上表mock结果记成真实模型通过。A06接通完整页面后，在现有ACCEPTANCE_RUNBOOK中补入同一T09的实际输入、更正、首次核对、补问及输出按钮顺序；无指引变体沿用事实摘要预期。成员只照实际步骤操作，不另建十五例比较模板；完整十五例计划仍按既有任务范围管理。

命令从本副本项目根目录执行；Windows使用npm.cmd，macOS使用npm。只执行本卡步骤要求的检查；需要浏览器时先构建并安装Chromium。前置新建命令由A实际验证后填工作包，成员不猜命令。
