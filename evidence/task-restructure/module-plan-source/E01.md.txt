## 顺序步骤

1. 运行 npm run build、npm run dev，在 Mock 加载 reviewed 并选 SUMMARY；只使用共用快照正文，不复制批准业务正文替换模拟身份。
2. 调整预览、复制反馈、Markdown／PDF 的呈现与换行；shared/export.ts 仅调整模板布局，不能改快照判定、字段、正文内容、文件名规则或模拟标记。
3. 从 handover 选两份稿分别预览与导出；对照案件号、对象、版本、正文和未核实项。Markdown与PDF含相同正文，换行差异可规范化，不能删段通过。
4. 运行 npm run build 后 npm run check:browser -- evidence/task-results/E01/run-01/browser，打开 evidence/task-results/E01/run-01/browser/ 内生成的摘要和 rendering-probe.pdf 全部页面，核对中文、长URL、文本表格与分页。复杂Markdown表格尚未实现，记录限制，不宣称已支持。
5. 逐项触发 Simulate output failure 后复制／MD／PDF，再取消重试，确认审核与预览不变；将PDF及逐页观察记录交 A。

## 固定检查与预期

| 输入／操作 | 应观察到的结果 |
|---|---|
| reviewed SUMMARY | 可预览复制导出，保留模拟／未批准标记与版本 |
| stale／save-error | 仍被快照门槛阻止，不能通过隐藏错误放行 |
| 长文探针与两稿 | 无缺字、截断或覆盖，正文不改；故障后同版本重试 |

命令从本副本项目根目录执行；Windows使用npm.cmd，macOS使用npm。只执行本卡步骤要求的检查；需要浏览器时先构建并安装Chromium。前置新建命令由A实际验证后填工作包，成员不猜命令。
