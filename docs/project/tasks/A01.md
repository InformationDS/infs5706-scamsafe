## 顺序步骤

1. 先按现有RUNBOOK执行npm run check、npm run check:business和npm run build，记录当前基座。复用获批技术与业务包，不重新选框架，不把pending模拟审核改成真实审核。
2. 在shared/runtime.ts确定运行案件、来源、字段／记录ID、版本、首次与最终审核、建议决定和输出依赖的统一结构；在shared/module-ports.ts明确模型分析、案件更新、建议和输出的输入／返回／错误／失效约定。写入MODULE_CONTRACTS，列每个模块的导出名称、props、回调、HTTP结构、保存确认和异步请求身份，不把接口设计留给四位成员各自决定。
3. 实现app/src/runtime-storage.ts：运行案件保存、刷新恢复、列表／打开和JSON备份基础。按PRD保护未保存修改、校验坏备份和同号确认。导入遇到未保存修改的组合规则未定时，先标为未支持并阻止覆盖，交A确认PRD后再开放；不自行增加弹窗行为。
4. 提供可直接启动的module-preview及固定注入端口：URL分别为/?module=intake、model、guidance、outputs；自动发现对应模块入口，不要求成员改主页面。无真实模块时显示明确的模拟替身。给B/C/D/E准备实际可显示的输入、模拟响应、保存回调、错误及重置操作，不能只交空函数签名。C的分析调用点及E的输出服务注册点由A预接到现有app.ts；分别能注入模拟实现，并在对应模块文件出现后使用其真实实现。E须能在独立预览实际生成并打开PDF，不等待A02挂载完整主页面。模块成员不需要修改公共路由。
5. 在runtime-fixtures及prototype.json给出T09主线与独立变体：2000→200、旧请求晚返回时250、部分回答／未知、3轮9问、主动结束、拒绝REC-03、角色／指引失效、无指引摘要、单稿编辑、保存／输出失败。每项写来源、动作、确定预期与禁止结果。新增角色或内容由A实际审阅；负向变体只供模拟，不进入正常批准配置。完整十五例保留扩展验收范围，不作为四模块开工条件。
6. 在MODULE_CONTRACTS固定B/C/D/E入口及文件所有权；在package.json提供npm run check:module -- 模块名 证据目录，实际验证四个模拟入口及重置。同步运行schema生成物与契约，记录生成器实际影响范围和差异。禁止覆盖固定来源快照或修改批准登记凑校验。
7. 运行核心、业务包、构建和module检查；把四模块使用的同一副本、输入、实际命令、URL及可观察预期填好后一次发放。未来模块尚未实现；通过仅表示公共起点就绪。

## 固定检查与预期

| 固定输入／动作 | 应观察到的结果 |

| 四个module URL及固定注入 | 都能启动、加载、重置；不依赖其他模块已完成，替身有mock标记 |
