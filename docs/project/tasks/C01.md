## 顺序步骤

1. 用/?module=model及A01提供的案件调用点开始，复用产品内API设置及服务适配器；保持默认Mock，可独立检查服务，不要求B先交界面。
2. 按冻结接口支持自由叙述及已有来源／记录的事实提议、候选分类、依据、缺口和补问提议；严格校验返回。模型不创建角色、批准、审核，不决定问题计数。原始叙述中的新记录按A01约定产生稳定候选ID，由B确认／合并，不沿用只允许已有固定字段的基座限制。
3. 更新实际intake提示与输出结构说明，未知／否／冲突分开、英语输出、保留来源、保护人工更正；建议仍由D生成。问题带目标与理由，但是否开轮和计数由B控制。
4. 实现超时、结构失败、当前请求与配置快照标识；失败保留原输入。设置保存不调用模型，密钥不回显、不进案件备份；保存失败保留旧配置。
5. 用本地假提供商核对T09、人工更正、指令干扰和无效响应；实际真实调用由人类在产品配置并主动执行，记录所用模型和结果。没有真实调用就标未执行，不为交卡索要密钥。
6. 运行npm run check、npm run build和A01实际验证的model模块检查；交实现、提示及失败结果，不另建十五例比较模板。主app.ts、package与公共运行schema变更交A处理。
