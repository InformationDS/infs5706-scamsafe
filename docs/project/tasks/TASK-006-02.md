## 读取与修改范围

- 读取：[完整样例](../../product/examples/WORKED_CASE.md)、[验收计划](../../../tests/README.md)、[PRD](../../product/PRD.md) 第4.1–4.4节。

## 输入与步骤

1. 沿用起始稿已填写的案例ID、合成标记、角色与来源；逐项核对对应原文，不另写一套叙述。A 确定机器格式后另开转换任务。
2. 逐行核对已有预期表中的前置、操作、结果和来源；只补“待 F 补充”的阅读核对和证据位置，不根据模型输出重写预期。
3. 覆盖金额更正、只答一问、未知不重复问、员工结束、拒绝建议、两份草稿、审核后改金额、刷新恢复；引用验收计划中的检查名称，不另造一套编号。
4. 分开两种前提：未审核指引应得到缺少有效依据的结果；指引实际获审核后才使用有建议的预期。标明所需角色和指引版本，不伪造已批准配置。
5. D逐条核对事实和合成指引，A核对产品规则。两份文件都记录真实审核结论。应用未运行时，执行结果一律未执行；预期审核通过不等于功能通过。

## 人工检查与完成条件

从输入稿逐项追溯预期：每个期望值有输入或指引依据；未知没有变成否／0；两份草稿引用同一案件；操作具有明确可观察结果。D的内容审核依赖已满足，D／A核对无冲突后验收案例文稿；没有应用不执行功能验收。

## 停止与反馈条件

样例与PRD冲突、指引尚未批准或预期无法独立确定时，记录对应检查项交 A。可以继续编写其他不受影响项，不修改标准迎合模型现有输出。
