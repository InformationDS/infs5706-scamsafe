## 顺序步骤

1. 核对四份副本与允许差异，先收齐再集中合并；模块内部问题退回原卡修复，不把全部业务重新写在主页面。跨模块共享结构由A调整并通知受影响成员一次同步。
2. 在PrototypeWorkbench连接C分析→B更正／首次核对／补问→D指引及建议→E摘要／草稿／最终审核／输出；接上A01保存与列表入口。每次变更通过统一状态端口，禁止各面板持有相互不同的当前案件。
3. 在公共服务挂载C模型与E输出校验，服务端重建并验证快照后导出。API配置、角色／指引变化和旧请求检查用同一案件／依赖身份；拒绝建议传播到输出，不用全案版本使无关草稿全部失效。
4. 实际从自由输入走通T09，不能用Load training state跳过提取／补问／审核。再走无指引摘要；保存刷新恢复、错误重试和多案不串案。使用mock时明确模式；真实调用由人类配置并主动完成。
5. PROTOTYPE_RUNBOOK写实际命令、URL、按钮、固定输入／答案、观察预期和重置。提供超时、无效响应、保存／输出失败、旧请求、上限、低权限／无指引的受控入口；F只操作，不改公共代码造故障。
6. 接入npm run check:prototype -- 证据目录，执行check、check:business、build和原型浏览器检查；把一个完整集成副本及简短操作交F。现有固定基座check:browser保留，其通过不能代替完整流程。
