## 目标与开工条件

把样例中的一个接报岗位和三条有限合成指引整理为可审核内容，供第一条流程使用。它们仍需审核，不因复制样例而有效。A 填好上述分配信息后可准备；不依赖运行接口。

## 读取与修改范围

- 读取：[完整样例](../../product/examples/WORKED_CASE.md) 第1、4–6节；[PRD](../../product/PRD.md) 对应条款。
- 可修改现有[岗位起始稿](../../../data/roles/EXAMPLE_ROLE_DRAFT.md)、[指引起始稿](../../../data/guidelines/EXAMPLE_GUIDELINES_DRAFT.md)：只核对已填写条目、补充来源和差异记录。不创建业务规则、机器结构或自动匹配代码。
- 更新本卡执行结果或对应 Issue；源教学样例的差异先报告 A，避免自行改预期来适配内容。

## 输入与步骤

1. 岗位稿已填 SYN Bank A / Intake Officer；逐行核对机构、职责、允许动作、越权边界及版本，与来源不符就记录差异，不另设计权限。接收方为 SYN Bank A 与 SYN Telco B 的人工岗位，不推定具备实际发送能力。
2. 逐行核对已填写 EX-G01–EX-G03 的必需条件、允许未知、失败结果、岗位、步骤、边界、来源和审核状态；不得自行决定新匹配门槛。
3. 状态初始均写“待审核”。逐条核对200金额更正、待处理状态、未知项和本地草稿边界，不能承诺冻结、退款或实际转介。
4. F独立检查条目是否有样例事实支持、是否与案例预期一致；A核对与PRD一致，记录内容审核结论。只有实际审核后才填审核人和日期，不代填通过。
5. 后续由 A 转为正式配置并确定版本映射；内容稿通过不等于配置已经接入。

## 人工检查与完成条件

打开两份稿：岗位权限明确；三条指引每个栏目齐全；REC-01/02各有依据；REC-03只是可选重复整理，拒绝不会删除事实。F与A完成内容审核并记录结论后验收内容稿。仍待审核时保持“待审核”，后续有效建议路径继续等待。
