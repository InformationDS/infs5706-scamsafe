## 顺序步骤

1. 在/?module=outputs使用A01的运行结构、固定T09事实与模拟建议。参考批准正文生成未审核摘要和银行／电信草稿，不能直接加载参考审核为真实员工通过。
2. 实现输出对象版本、依赖、编辑历史和Employee edited标记；生成／重算保留员工内容并提示确认。拒绝建议不得继续作为待执行事项，只有依赖受影响对象失效。
3. 完成最终审核界面及事件绑定；检查最新事实／分类、建议和各输出，保留不确定性。B负责首次核对，E消费其确认／变更信息；最终审核绑定对象与依赖，不要求无指引路径接受不存在的建议。
4. 实现统一快照资格与复制、Markdown／HTML／PDF正文；无指引只形成事实摘要。未保存、待确认或过期审核阻断；输出失败保留正文和有效审核，同版本可重试。提供可在服务端复验的纯函数及server/src/output-service.ts，接到A01预留输出注册点，独立检查时即可实际生成PDF。A02装配完整页面沿用同一服务，不在公共路由加另一套资格判断。
5. 完成本模块预览、排版和UI。样式放outputs/style.css并加模块作用域，不改全局CSS；用固定建议端口完成单稿修改／另一稿保持和两稿共享事实变更检查，不等D。
6. 运行npm run check、npm run build及outputs模块检查；实际生成PDF并逐页观察中文、长文本及表格，记录真实限制。交回模块和文件，不把单系统结果写为两系统都通过。
