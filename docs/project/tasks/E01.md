#### 实际实现与对象规则

- `outputProposals`只从当前结构化事实、来源／更正历史、候选分析及D的实际active/actionable建议生成；没有复制参考正文的审核措辞。摘要和有效银行／电信稿初始无E审核。保留未知、冲突、报告属性、合成／pending和未执行边界。
- 使用D的实际匹配、决定及版本。拒绝／失效步骤不进入新生成的待办正文；历史稿保留但标inactive／需更新，并在输出资格中阻断。REC-03变化不影响未引用它的银行审核。没有有效指引时新提议只有事实摘要和固定`Insufficient approved guidance; human review required`，不生成机构路径或接收方稿。
- 每对象独立版本、实际事实／analysis／角色／指引／建议依赖；不依赖整个case version或另一稿版本。实际正文不展示无独立版本键的补问计数／状态；只展示当前事实中的应对和有引用的来源，避免把无版本跟踪的界面计数当作已审核正文。
- `editOutput`记录原文、理由、actor、Employee edited；单稿修改不改共用事实。重新生成遇员工内容先比较，必须明确替换并填actor／理由；保留历史。可选择保留员工稿并刷新其他稿，或取消全部比较。受影响而未更新的员工稿继续阻断，不能靠编辑或审核获得新权限。
- 最终审核有显式复选确认、员工标识和逐对象按钮；确认绑定当前case／instance／version／选定对象，内容变化会清除确认。事件记录对象版本、依赖、actor及时间。建议需实际D接受／修改且非模拟决定，再单独最终审核；输出引用的建议也须有有效最终审核。模拟参考审核没有升级。
- `outputSnapshot`是预览、复制、Markdown及PDF共用纯函数资格；服务再次调用它。未保存、needsFactConfirmation、未核对事实、依赖变化、旧／模拟审核、拒绝／失效建议或无依据接收方均阻断。正文编辑区仅供核对，与有效快照预览明确分开。
- `exportRuntime`由A01已有注册点发现，`/api/runtime/context`实际返回outputRegistered=true；复用已有`/api/runtime/export`。旧`/api/export`和旧serializer保持兼容。服务不另存案件。失败不改正文、版本或有效审核，允许同版本重试。
- 正式HTML仅渲染安全转义的标题／文本／表格子集，无远程资源或任意HTML；PDF用本机Chromium、重复表头、页脚、换行和CJK字体回退。不同格式来自同一有效snapshot。
