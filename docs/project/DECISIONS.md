# 项目决定日志

当前有效需求见 [PRD](../product/PRD.md)。下表保留讨论中已确认的决定；实施变更需要补充理由、受影响接口及验收项。

## 已确认产品决定

| 日期 | 决定 | 理由 |
|---|---|---|
| 2026-10-12 | 作业指南未要求锁定单一行业；跨行业共用核心流程可作为方案方向，仍需明确各成员机构的员工权限与责任。 | 作业对象是联盟成员机构中接收疑似诈骗报告的授权一线员工；AI 只提供建议，授权员工审核和行动。 |
| 2026-10-12 | 暂按跨行业共用核心流程推进 PRD。 | 用户要求在澄清行业范围后继续；具体机构的权限和演示场景留待后续定义。 |
| 2026-10-12 | 原型需完成信息补全与矛盾检查、处理路径建议、交接记录生成三项能力；不以单项功能作为最终范围。 | 用户明确要求三项都完成。 |
| 2026-10-12 | 在信息补全之前增加疑似诈骗类型识别；系统必须处理多个类型，不能依赖单一预设案例。 | 用户明确要求输入案例后先识别类型。作业限制 AI 不得自行确认诈骗成立，因此结果须写为“疑似类型”。 |
| 2026-10-12 | 首版识别五类疑似诈骗：投资、付款重定向、恋爱、网络钓鱼、远程访问；另区分“其他类型”和“信息不足，待确认”，允许多标签。 | 用户接受以 ACCC 2025 报告损失最高的五类作为首版范围。 |
| 2026-10-12 | 员工以自由描述录入案例；系统提取到内置结构化表单，用于分类与分析，并按需补问。 | 用户明确指定输入与表单联动方式。 |
| 2026-10-12 | 每轮最多提出 3 个关键补问；员工补充后更新表单与分析，再决定是否需要下一轮。 | 用户选择每轮最多 3 问的交互方式。 |
| 2026-10-12 | 采用已提出的停止条件；最多 3 轮，每轮最多 3 问，总计最多 9 个补问。 | 用户明确认可停止条件，并选择有限轮次。 |
| 2026-10-12 | 每案开始时由员工选择所属机构和岗位，从原型配置带入对应权限。 | 用户选择每案选择角色的方式，便于测试不同机构视角。 |
| 2026-10-12 | 多机构案件列出多个相关去向，并说明优先顺序、各自职责和当前员工可做的步骤。 | 用户选择呈现多个处理去向。 |
| 2026-10-12 | 交接采用统一案件摘要＋按接收机构／岗位分别生成草稿。 | 用户选择接收方相关的交接内容；各草稿共用同一案件事实和版本。 |
| 2026-10-12 | 首版使用团队编写并审核、明确标注为合成的有限指引。 | 用户选择预置合成指引；不把 ACCC 年度报告作为联盟操作手册。 |
| 2026-10-12 | 设置首次分析后的事实／疑似类型核对，以及交接导出前的最终审核两个节点。 | 用户选择两个明确审核节点。 |
| 2026-10-12 | 记录支持页面预览、复制，以及 Markdown、PDF 两种下载格式。 | 用户明确要求四种输出能力。 |
| 2026-10-12 | 首版采用 15 个固定合成案例：5 个完整、5 个缺失／冲突、3 个混合／未知、2 个权限／指引边界案例。 | 用户选择首版测试规模 15 个。 |
| 2026-10-12 | 同屏分为信息／工作流区与聊天区；聊天承担角色选择、自由描述和补问，工作区展示结构化信息、分析、审核与输出。 | 用户明确提出双区域布局。左右比例、具体样式尚未确定。 |
