# 架构与模块职责

状态：面向协作开发的架构草案；技术栈、模型服务商和部署环境未选定，没有运行代码。

## 数据流

```text
app：聊天 + 工作流 + 两次审核 + 本地历史
  → server：模型适配、提取、分类、补问、指引匹配、建议、草稿
  ← 结构化、带案例版本和来源的结果
app：最终审核 → 同一份数据生成复制 / Markdown / PDF
```

浏览器维护单人合成案件状态；分析服务处理模型调用，模型凭证放在服务端环境配置。导出由共享的已审核快照驱动，具体渲染位置待技术任务决定。多人协作开发通过 Git，不建立产品的多人案件服务器。

| 工作范围 | 目录 | 可先完成的交付 | 依赖 |
|---|---|---|---|
| 共享契约 | `data/schemas/` | schema、稳定枚举、案例版本与状态 | PRD、字段字典 |
| 指引与评估 | `data/roles/`、`data/guidelines/`、`data/evaluation/` | 配置、合成指引、预期结果 | 共享契约 |
| 界面 | `app/` | 双栏、角色选择、表单、补问、审核 | 共享契约，可用明确标注的 mock |
| 分析服务 | `server/` | 模型适配与处理流程 | 契约、指引、模型条件 |
| 历史与输出 | `app/` 中独立模块 | 本地恢复、版本失效、双格式输出 | 案件／审核契约 |
| 集成验证 | `tests/`、`evidence/test-results/` | 流程测试、实际结果与复测 | 应用、评估数据 |

## 先约定，再并行

首先完成 [CONTRACTS.md](CONTRACTS.md) 中的接口与 schema 任务。成员围绕同一案件结构开发，避免各自独立定义角色、问题、建议和审核结果。

涉及共享契约的变更必须标注兼容性和受影响模块。界面开发的 mock 要与正式 schema 校验一致，但 mock 演示不能算模型功能已完成。合成指引、角色和测试案例须有版本及审核标记。

具体框架、包结构、调用端点、运行命令和超时参数在技术选型后新增；当前目录说明不替代实现。
