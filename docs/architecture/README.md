# 统一技术方案入口

维护人：A。这里定义各任务共用的技术决定；成员根据任务卡读取相关段落，不自行选择框架或另建接口。

## 当前架构边界

```text
app：输入、事实核对、补问、审核、历史与输出
  → server：模型调用、结构校验、分类、指引匹配、建议与草稿
  ← 带来源和版本的统一结果
app：有效审核快照 → 预览、复制、Markdown、PDF
```

原型采用单人本地合成案件历史；服务端保管模型凭证。共享案件状态、审核有效性、持久化和导出内容源由 A 统一实现，成员在固定入口内完成界面、提示内容、配置和版式任务。

## 先建立什么

1. A 完成 [TASK-011-01](../project/tasks/TASK-011-01.md) 的技术与运行方案。
2. 建立可运行骨架，并把真实启动与检查命令写入运行说明。
3. 根据[接口要求](CONTRACTS.md)和[完整样例](../product/examples/WORKED_CASE.md)定义共享结构，提供可校验的同一份模拟数据。
4. 在具体任务卡填入已有输入、实际文件范围和检查方式，才开放代码任务。

内容、界面操作稿和排版稿可以先准备；它们不确定机器字段名或业务状态。模型暂不可用时可以用明确标记的共享 mock 做界面联调；真实模型验收单独记录。

## 文件归属

| 位置 | 维护职责 |
|---|---|
| 根依赖、运行配置、data/schemas/、共享状态与基础服务 | A |
| app/ 中指定的展示组件与排版模板 | B、E 按任务卡分开修改 |
| 指定的模型提示内容 | C；调用、结构校验与错误处理由 A 维护 |
| data/roles/、data/guidelines/ | D 提供内容，A 接入统一结构 |
| data/evaluation/、实际验收记录 | F，D 核对内容；检查工具由 A 提供 |

未在任务卡中确定的路径不作为可修改范围。接口变化由 A 同步结构、样例和受影响任务，再安排消费者更新。
