# 共享数据与接口约定任务

状态：契约要求已列出，尚未创建 JSON Schema 或调用接口。

## 需定义的对象

1. `CaseRecord`：机构／岗位上下文、原始叙述、重复事实记录、来源元数据、版本与历史。
2. `AnalysisResult`：候选类型、不确定点、紧急提示、关联事实及所用案例／指引版本。
3. `FollowUpRound`：稳定轮次／问题标识、1–3 个问题、目标字段及适用记录编号、原因、回答历史和状态、计数依据及全案停止状态。规则见 PRD 4.2。
4. `Guideline` 与 `RoleProfile`：编号、版本、有效性、审核状态、职责和配置权限；指引条件分别记录必须满足、允许未知及不满足结果。
5. `Recommendation`：负责方、任务、优先级、依赖、权限、事实与指引引用、局限。
6. `HandoverDraft`：拟接收方、统一事实引用、相关摘要、未解决事项、建议及自身／依赖版本；统一摘要也须能独立引用和审核。
7. `ReviewRecord`：阶段、审核人、时间、案例／对象版本、接受／修改／拒绝及理由。
8. `ExportSnapshot`：最终审核有效的选定摘要／草稿及一致的 Markdown／PDF 内容源。

字段语义以 [FIELD_DICTIONARY.md](../product/FIELD_DICTIONARY.md) 为准。字段编号不等同于已经确定的 JSON 属性名；属性名和英文枚举由 TASK-005 定义并审阅。

## 必须保持的不变量

- 未知、否定、不适用和冲突分别表示；未知金额不能成为 0。
- 多条事件／交易有稳定 ID，来源与引用可校验；同笔交易更新不重复计入。金额按币种和交易状态分别汇总，未知单列，不换汇或称为已确认损失；模型不得凭空创建指引或权限。具体规则见 PRD 4.1。
- 内容变化更新版本；分析、摘要、建议、草稿和审核记录引用所依赖的内容版本。纯排版或相同结果的重复处理不使内容审核失效。不能仅凭案件全局版本变化把所有未受影响对象一律失效，也不能把旧审核直接改绑新版本。
- 员工确认更正优先，重新分析不覆盖；不同提取值作为冲突候选保留来源，待员工决定。员工已修改的草稿也不被重算静默覆盖。
- 审核阶段只有首次核对和最终审核。保留首次核对历史；首次核对后直接修改事实／分类或重分析出现变化时，记录变更核对后继续。正常补问产生的更新在最终审核核对。
- 角色切换使受影响建议／草稿的最终审核失效，不删除事实、首次核对历史或补问计数。
- 建议拒绝记录保留；摘要／草稿的待执行内容过滤拒绝建议，引用内容变化使对应摘要／草稿审核失效。重新分析不自动撤销拒绝决定。
- 草稿内容或接收方变化只使对应草稿审核失效；更改共用事实、角色或指引时按实际依赖传播。具体操作矩阵以 [PRD 第 4.4 节](../product/PRD.md)为准。
- 同案补问最多 3 轮、9 问，计数、部分回答与停止行为统一遵循 [PRD 4.2](../product/PRD.md)。问题目标定位字段及适用记录；同一目标的同一未知缺口不重复问。主动结束后不新增问题；后来主动回答可更新原问题及事实，保留历史、不计新问、不重开补问。
- 无有效适用指引时只产生事实摘要，仍须最终审核后才能本地复制／下载；不产生具体建议、机构路径或接收方草稿。恢复有效指引后新增输出另行审核，详见 [PRD 4.3](../product/PRD.md)。
- 只允许有效最终审核的快照用于已审核复制／下载；Markdown 与 PDF 共用快照。
- 异步结果只有在依赖内容仍适用且仍为该操作当前请求时才能更新状态；旧请求晚返回不得覆盖新内容、人工修改、计数或审核，也不能复活失效审核，详见 PRD 6。
- 错误响应需要区别可重试的服务失败、输入／结构问题和无指引依据的业务状态。

## 契约变更流程

由 A 负责共享契约及技术审核。执行成员发现缺字段或规则冲突时，在任务中说明输入、预期输出和阻塞原因，交 A 决定，不自行扩展共享接口。变更须同步受影响的 PRD／字段字典、schema、mock、实现与测试；尚未存在的实现明确标为待建立。技术选型与机器可读结构仍须由契约任务落实，本文件不代表接口已经可调用。
