# 共享数据与接口约定任务

状态：契约要求已列出，尚未创建 JSON Schema 或调用接口。

## 需定义的对象

1. `CaseRecord`：机构／岗位上下文、原始叙述、重复事实记录、来源元数据、版本与历史。
2. `AnalysisResult`：候选类型、不确定点、紧急提示、关联事实及所用案例／指引版本。
3. `FollowUpRound`：轮次、0–3 个问题、目标字段、原因、回答和状态，以及全案计数。
4. `Guideline` 与 `RoleProfile`：编号、版本、审核状态、适用条件、职责和配置权限。
5. `Recommendation`：负责方、任务、优先级、依赖、权限、事实与指引引用、局限。
6. `HandoverDraft`：拟接收方、统一事实引用、相关摘要、未解决事项、建议和版本。
7. `ReviewRecord`：阶段、审核人、时间、案例／对象版本、接受／修改／拒绝及理由。
8. `ExportSnapshot`：最终审核有效的选定摘要／草稿及一致的 Markdown／PDF 内容源。

字段语义以 [FIELD_DICTIONARY.md](../product/FIELD_DICTIONARY.md) 为准。字段编号不等同于已经确定的 JSON 属性名；属性名和英文枚举由 TASK-005 定义并审阅。

## 必须保持的不变量

- 未知、否定、不适用和冲突分别表示；未知金额不能成为 0。
- 多条事件／交易有稳定 ID，来源与引用可校验；模型不得凭空创建指引或权限。
- 每次输入或事实更正更新案例版本；分析、草稿和审核标记依赖版本。
- 角色切换会影响建议与审核，不删除已收集事实。
- 同案补问计数不因分析重试、切换角色或刷新而重置。
- 只允许有效最终审核的快照用于已审核复制／下载；Markdown 与 PDF 共用快照。
- 错误响应需要区别可重试的服务失败、输入／结构问题和无指引依据的业务状态。

## 契约变更流程

在任务／PR 中说明变更对象、原因、兼容性、数据迁移和受影响消费者；同步 PRD／字段字典、schema、mock、实现与测试。通过审核后合并，其他模块据版本更新。GitHub 尚未设置时，记录在任务索引与决定日志中。
