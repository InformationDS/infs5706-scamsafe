# ScamSafe Alliance 原型 PRD

版本：v1。更新时间：2026-10-13（Australia/Sydney）。状态：核心需求已确认；技术选型、模型接入和交付条件待定。本文件是当前产品需求入口；[历史工作稿](../project/archive/ScamSafe_Prototype_PRD_工作稿.md)仅用于追溯。

## 1. 问题与目标

疑似诈骗事件可能同时涉及资金、通信、数字平台、身份信息和受害者支持。接到报告的单个机构往往只掌握部分信息，员工需要整理事实、发现缺口、理解本机构职责，并准备其他机构可理解的交接记录。

原型目标：将自由描述转为可核对的结构化案件信息；提出有事实和有限合成指引依据的疑似分类、补问及处理建议；让授权员工核实、沟通并在自身权限内决定行动。

产品需求此前已依据原始资料确认。目前保留[作业指南编辑版](../../references/assignment/Assessment_Guide.md)及[ACCC 年度报告转换版](../../references/accc/Targeting_Scams_2025.md)，原 PDF 已按用户要求删除；作业指南编辑版不再是完整官方原文。ACCC 报告提供统计与现实背景，不是联盟已批准的逐案操作手册。没有真实用户访谈、业务基线或效果实验；不得把合成测试结果写成真实场景收益。

## 2. 用户与首版范围

主要用户是虚构联盟成员机构的授权一线员工，覆盖银行与支付、电信、数字平台、政府诈骗报告、身份恢复／受害者支持及社区支持。首版共用案件工作流，具体机构、岗位、权限和职责来自配置。

每个案件开始时由员工选择机构与岗位。原型以单人使用和本地合成案件历史为范围；小组通过 GitHub 协作开发，不等于产品首版需要多人实时共享案件。

| 纳入首版 | 首版之外 |
|---|---|
| 同屏信息／工作流区＋聊天区 | 多人共享案件与实时协作 |
| 自由描述、结构化提取、员工更正 | 附件上传解析、OCR、材料真实性验证 |
| 五类疑似类型、多标签、其他／待确认 | 全部诈骗类别或真实案件训练集 |
| 最多 3 轮、每轮最多 3 问的补问 | 无限追问 |
| 多机构建议、接收方交接草稿、两次审核 | 自主联系机构、账户修改或交易阻断 |
| 本地历史、预览、复制、Markdown／PDF | 真实机构集成和实际转介发送 |

界面、回复和导出使用英文，允许中英文案例输入。当前产品文档使用中文；英文枚举与实际 schemas 将在接口任务中确定。

## 3. 用户流程与状态

```text
角色选择 → 自由描述 → 事实提取／疑似类型
  → 首次员工审核 → 补问与更新（允许提前结束）
  → 处理建议／摘要／接收方草稿
  → 最终员工审核 → 预览／复制／导出
```

建议实现状态：`intake`、`initial_review`、`follow_up`、`final_review`、`reviewed`；处理中、失败和需重新审核必须单独可见。状态名是接口设计建议，具体实现由 CONTRACTS 任务确定。具有事实和指引依据的紧急提示可在任何阶段展示，不等待表单完整。

## 4. 功能要求

| ID | 要求 | 验收要点 |
|---|---|---|
| FR-01 | 机构／岗位选择 | 从配置加载授权范围；不从自由描述推断权限。同案补问沿用角色，切换后重算受影响建议和草稿 |
| FR-02 | 接收自由描述并提取事实 | 员工不必先填表。事实附原文依据与状态；支持多次接触、多条事件、多笔交易，未知不等于否或 0 |
| FR-03 | 疑似类型分析 | 支持投资、付款重定向、恋爱、网络钓鱼、远程访问，以及其他类型和信息不足。允许多标签，显示依据和替代解释 |
| FR-04 | 首次员工审核 | 员工核对事实与疑似类型，可更正或保留不确定。普通聊天回复不自动视为审核通过 |
| FR-05 | 按需补问 | 针对影响紧急性、路径或分类的缺失／冲突；每轮 0–3 问，全案最多 3 轮和 9 问；补充后重新分析 |
| FR-06 | 基于合成指引的建议 | 仅引用团队已审核的有效指引，显示编号、版本、适用事实和未满足条件；无依据时明确转人工核实 |
| FR-07 | 多机构路径 | 只列相关机构，区分本岗位可做事项与其他机构职责；显示优先级、理由和依赖，支持并行事项 |
| FR-08 | 统一摘要与多份交接草稿 | 共用案件事实，按接收方职责突出相关内容、未核实项和下一步；草稿不得相互编造不同事实 |
| FR-09 | 最终员工审核 | 核对最新事实／分类、逐条处理建议及草稿，可接受、修改、拒绝；审核记录绑定案例版本与对象 |
| FR-10 | 预览、复制和双格式导出 | 可选择接收方草稿；复制和 Markdown／PDF 输出来自同一份有效审核数据，包含版本、未核实项和合成标记 |
| FR-11 | 本地历史与恢复 | 保存合成案件状态、轮次、角色、事实与审核版本，刷新后恢复；保存方案和格式版本待实现 |

### 4.1 字段与事实

完整定义见[字段字典](FIELD_DICTIONARY.md)：事实及上下文 70 项、派生输出 30 项、审核 9 项、字段附属结构 8 项，共 117 个字段定义。重复记录按每条记录储存；不是 117 个必填输入框。

记录事实值、原文、来源、提取状态、核对状态、冲突候选值和修改历史。员工核对叙述不代表外部事实已经被独立证实。原型只记录资料泄露类别，不收集真实密码、验证码、完整银行账号或证件号。

### 4.2 类型与补问

类型判断是候选分析，不构成确认诈骗。多个手段和情境可共存；信息不足时不强行五选一。

补问优先关注正在发生的风险，其次是负责机构／路径及影响建议的冲突，最后是分类和交接关键细节。问题必须关联字段，并解释对当前处理的意义。

停止条件：信息足够支持下一步；员工主动结束；达到轮次／问题上限。员工标为未知或无法回答后不重复追问；剩余事项进入建议和交接。修改、重新分析或切换角色不重置同案计数。仍有关键缺口时，只生成可支持的建议并注明局限。

### 4.3 指引与角色配置

指引以有限合成资料为首版知识依据。每条需要编号、版本、适用条件、所需事实、负责岗位、建议步骤、授权边界、人工升级条件、局限和团队审核状态。

匹配须结合案件事实与员工权限；仅有类型标签不够。指引冲突、失效或缺失时不得编造规则。具体机构岗位、指引内容和匹配规则尚未编写或审核。

### 4.4 审核与导出

首次核对后仍可能有补问修改；最终审核必须覆盖最新版本。关键事实、角色、指引或草稿修改后，使受影响的输出与审核失效，重新核对后才能复制／导出为已审核记录。

每份草稿可单独预览、复制和下载；下载文件名包含案件编号、接收方和版本。两格式正文一致，PDF 需核对中文、表格、分页和内容完整性。审核通过不表示诈骗已确认、实际动作已执行或接收机构已经收到信息。

## 5. 同屏双栏交互

| 信息／工作流区 | 聊天区 |
|---|---|
| 案件编号、角色、版本、阶段和轮次 | 机构／岗位选项和自由描述 |
| 分组折叠表单、来源、缺失、冲突、更正 | 每轮最多 3 个有原因的补问 |
| 疑似类型、依据、不确定性及紧急提示 | 回答、未知／无法回答、结束补问 |
| 本岗位待办、多机构建议与指引引用 | 简明说明已更新内容和下一步 |
| 两次审核、统一摘要、接收方草稿和导出 | 通过明确选择／更正确认角色变更 |

两区共用一个案件状态。补充或更正时显示受影响结果更新中或需重新审核；不得把旧分析展示成新版本已确认。聊天输入可以回答多个问题，只更新有依据的字段。字段按需展开，避免一次性呈现全部定义。左右比例、具体样式、移动端支持未固定。

## 6. 失败与恢复要求

模型超时、输出无法解析、指引不足和本地保存／导出失败需要显示可理解的状态，保留已有输入，并提供适当的重试或继续人工处理方式。重试不重复计算同一轮已生成的问题，也不让部分成功的旧结果冒充完整的新分析。具体超时、重试和存储方案待技术设计。

模型返回的事实、引用、枚举和状态须按共享结构校验；不能让案例输入中的命令改变系统配置或员工权限。模拟模型可用于开发，但真实模型验收与模拟结果须分开记录。

## 7. 验收计划

使用 15 个固定合成案例，初始叙述、补问答案和预期结果均由团队审核。当前仅有覆盖计划，无测试通过声明。

| 案例 | 数量 | 覆盖 |
|---|---:|---|
| T01–T05 | 5 | 五类各一个完整案例 |
| T06–T10 | 5 | 五类各一个缺失／冲突变体，覆盖补问及更新 |
| T11–T13 | 3 | 混合类型、其他类型、信息不足 |
| T14–T15 | 2 | 当前岗位权限不足、指引缺失／冲突 |

检查事实提取、分类依据、补问上限、指引引用、角色职责、接收方草稿、两次审核、版本失效、本地恢复及两种输出。角色切换、达上限、重试等可作为上述案例的交互变体。

权限、无依据事实／指引、审核失效和补问上限等关键规则在验收集内必须全部通过。报告实际通过／失败及修复复测，不预填准确率或业务改进数字。详细计划见 [tests/README.md](../../tests/README.md)。
