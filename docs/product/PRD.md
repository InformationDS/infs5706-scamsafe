# ScamSafe Alliance 原型 PRD

本文件是产品行为的唯一依据；实现及测试进度见[项目状态](../project/STATUS.md)。

## 1. 问题与目标

疑似诈骗事件可能同时涉及资金、通信、数字平台、身份信息和受害者支持。接到报告的单个机构往往只掌握部分信息，员工需要整理事实、发现缺口、理解本机构职责，并准备其他机构可理解的交接记录。

原型目标：将自由描述转为可核对的结构化案件信息；提出有事实和有限合成指引依据的疑似分类、补问及处理建议；让授权员工核实、沟通并在自身权限内决定行动。

原型使用合成案例和合成指引。ACCC 报告只提供统计与现实背景，不是联盟已批准的逐案操作手册；合成测试结果不能写成真实场景收益。

## 2. 用户与原型范围

主要用户是虚构联盟成员机构的授权一线员工，覆盖银行与支付、电信、数字平台、政府诈骗报告、身份恢复／受害者支持及社区支持。原型共用案件工作流，具体机构、岗位、权限和职责来自配置。

每个案件开始时由员工选择机构与岗位。原型以单人使用和本地合成案件历史为范围。

| 纳入原型 | 原型范围之外 |
|---|---|
| 同屏信息／工作流区＋聊天区 | 多人共享案件与实时协作 |
| 自由描述、结构化提取、员工更正 | 附件上传解析、OCR、材料真实性验证 |
| 五类疑似类型、多标签、其他／待确认 | 全部诈骗类别或真实案件训练集 |
| 最多 3 轮、每轮最多 3 问的补问 | 无限追问 |
| 多机构建议、接收方交接草稿、两次审核 | 自主联系机构、账户修改或交易阻断 |
| 本地历史、预览、复制、Markdown／PDF | 真实机构集成和实际转介发送 |

界面、回复和导出使用英文，允许中英文案例输入。

## 3. 用户流程与状态

```text
角色选择 → 自由描述 → 事实提取／疑似类型
  → 首次员工审核 → 补问与更新（允许提前结束）
  → 有有效指引：处理建议／摘要／接收方草稿
    无有效指引：仅事实摘要（见 4.3）
  → 最终员工审核 → 预览／复制／导出
```

处理中、失败和需重新审核必须清楚可见。风险关注提示仅使用固定合成案例和指引中明确的条件，不计算风险分数；有依据时可在首次核对前展示，但标为据报告、尚未核对，不等待表单完整。全流程只有首次核对和最终审核两个审核节点。

## 4. 功能要求

| ID | 要求 | 验收要点 |
|---|---|---|
| FR-01 | 机构／岗位选择 | 从配置加载授权范围；不从自由描述推断权限。同案补问沿用角色，切换后重算受影响建议和草稿 |
| FR-02 | 接收自由描述并提取事实 | 员工不必先填表。事实附原文依据与状态；支持多次接触、多条事件、多笔交易，未知不等于否或 0 |
| FR-03 | 疑似类型分析 | 支持投资、付款重定向、恋爱、网络钓鱼、远程访问，以及其他类型和信息不足。允许多标签，显示依据和替代解释 |
| FR-04 | 首次员工审核 | 员工核对事实与疑似类型，可更正或保留不确定。普通聊天回复不自动视为审核通过 |
| FR-05 | 按需补问 | 针对影响紧急性、路径或分类的缺失／冲突；有需要时每轮 1–3 问，全案最多 3 轮和 9 问；不需补问时不建立新轮次，补充后重新分析 |
| FR-06 | 基于合成指引的建议 | 仅引用团队已审核的有效指引，显示编号、版本、适用事实和未满足条件；无依据时明确转人工核实 |
| FR-07 | 多机构路径 | 只列相关机构，区分本岗位可做事项与其他机构职责；显示优先级、理由和依赖，支持并行事项 |
| FR-08 | 统一摘要与多份交接草稿 | 共用案件事实，按配置的接收方职责突出相关内容、未核实项和有依据的下一步；无有效指引时仅形成事实摘要 |
| FR-09 | 最终员工审核 | 核对最新事实／分类、摘要及已有建议／草稿，可接受、修改、拒绝；仅摘要路径不要求不存在的建议／草稿，审核记录绑定案例版本与对象 |
| FR-10 | 预览、复制和双格式导出 | 可独立选择统一摘要或选择接收方草稿；复制和 Markdown／PDF 输出来自同一份有效审核数据，包含版本、未核实项和合成标记 |
| FR-11 | 本地历史与恢复 | 保存合成案件状态、轮次、角色、事实与审核版本，刷新后恢复 |
| FR-12 | 模型 API 设置 | 员工可在产品内选择模拟或真实 API 模式，填写 OpenAI 兼容服务的地址、模型名称、密钥及必要认证参数；保存不自动调用模型，下一次主动分析使用新配置 |

### 模型 API 设置

工作台提供独立设置入口。用户可设置 API 基地址、模型名称、API Key、认证头／前缀及请求超时；默认使用模拟模式。切换真实 API 模式时必须有完整配置，并说明主动分析将向所配置服务发送当前合成案件，可能消耗服务额度。保存设置本身不发送模型请求，也不声称连接测试成功。

密钥只在输入时进入页面，保存后页面不回填原值，仅显示是否已保存；留空表示保留，清除需明确选择。配置在当前电脑的本地服务端保存，不进入案件 JSON 备份、浏览器案件存储或共享提交。保存失败时保留旧有效配置并允许重试；保存成功后下一次分析即生效，无需重启。更改模型设置不能更改岗位权限、案件事实、补问计数或审核记录；使用旧配置发起的未完成结果不得在页面冒充新配置结果。

### 4.1 字段与事实

完整定义见[字段字典](FIELD_DICTIONARY.md)：事实及上下文 70 项、派生输出 30 项、审核 9 项、字段附属结构 8 项，共 117 个字段定义。重复记录按每条记录储存；不是 117 个必填输入框。

记录事实值、原文、来源、提取状态、核对状态、冲突候选值和修改历史。员工核对叙述不代表外部事实已经被独立证实。原型只记录资料泄露类别，不收集真实密码、验证码、完整银行账号或证件号。

员工明确确认的更正优先作为当前记录。重新分析原始描述或补充回答时，不得静默覆盖更正；若出现不同值，保留当前更正和新候选值及来源，标记冲突，由员工选择保留或再次更正。模型不得自行消除冲突。例如员工将金额从 2000 更正为 200 后，重读原叙述不能把金额自动改回 2000。

每笔交易保留独立编号；补充同一笔交易时更新该记录，不重复计入。金额按币种和交易状态分别汇总，区分仅被要求付款、据报待处理、据报已完成及状态未知／冲突；不同币种不相加、不自动换汇。金额或币种未知的记录单列数量与缺口，不当作 0。所有金额均为已记录的报告值，不标为已确认损失；缺失信息和未解决冲突须随汇总显示。

### 4.2 类型与补问

类型判断是候选分析，不构成确认诈骗。多个手段和情境可共存；信息不足时不强行五选一。

补问优先关注正在发生的风险，其次是负责机构／路径及影响建议的冲突，最后是分类和交接关键细节。问题必须关联目标字段；属于重复记录的字段还须关联具体记录编号，并解释对当前处理的意义。例如 E09 / TX-01 与 E09 / TX-02 是不同目标。

停止条件：信息足够支持下一步；员工主动结束；达到轮次／问题上限。员工标为未知或无法回答后，不再对同一目标的同一缺口换措辞重复询问；其他记录的相同字段仍可按需补问。修改、重新分析或切换角色不重置同案计数。仍有关键缺口时，只生成可支持的内容并注明局限。

| 操作或情况 | 确定规则 |
|---|---|
| 一轮问题生成成功 | 1–3 个问题首次成功展示且保存后，计 1 轮；问题总数按本轮实际问题数增加。没有问题时不计轮次 |
| 生成或保存失败、重试、刷新恢复 | 不重复计数；已计数的问题保留原编号、轮次和回答，不重新生成一组替代问题绕过上限 |
| 只回答本轮部分问题 | 保存回答并更新有依据的事实；仍停留当前轮，不立即开启下一轮 |
| 本轮问题全部处理 | 每问均为已回答、未知／无法回答或已不适用后，评估是否需要下一轮；未知／无法回答项保留缺口，不重复询问 |
| 员工主动结束补问 | 未答问题标为已跳过并保留缺口；进入可支持的输出，不把跳过当成已回答。同案不再新增补问 |
| 补问停止后收到主动补充的信息 | 仍可记录来源、更新事实与分析；不自动恢复补问或重置计数。受影响输出按 4.4 重新审核 |
| 原标为未知／无法回答／已跳过，后来提供答案 | 更新原问题的回答和状态并保留历史，不建立新问题、不新增计数。人工更正保护与 4.4 的审核规则继续适用 |
| 达上限 | 不再新增问题；已展示的当前轮仍可回答或标记未知／无法回答／不适用，处理后结束，也可主动提前结束。保留剩余缺口并注明建议局限 |

### 4.3 指引与角色配置

指引以有限合成资料为原型知识依据。每条需要编号、版本、有效性、团队审核状态、负责岗位、建议步骤、授权边界、人工升级条件和局限，并将事实条件分为以下三项：

- 必须满足：指明字段／记录及允许值；这些条件必须有当前事实支持。
- 允许未知：明确哪些字段可以缺失或保持未知，以及对步骤的限制；没有列入这一项的必需条件不能用未知代替满足。
- 不满足时：不输出该指引支持的步骤，保留具体缺口或冲突供员工核实。冲突不得由模型自行选值；只有指引明确允许该冲突状态时才可匹配。

匹配须结合案件事实与员工权限；仅有类型标签不够。只有团队已审核、当前有效、条件满足且符合岗位权限的指引才可支持系统生成的建议。部分指引不可用时，只生成其余有完整依据的步骤，明确被省略部分及原因；不借用无关指引补齐。指引相互冲突时不生成有争议的步骤，保留双方引用与冲突说明。尚未获批的教学或负向样例须保留待审核标记；当前有限批准内容以data/business登记为准，不能由样例名称推定批准。

若没有任何有效适用指引，显示 **“Insufficient approved guidance; human review required”**。员工仍可核对事实、查看有依据的疑似类型、按 4.2 补问或主动结束，再生成仅含事实、来源、候选类型及依据、缺口和已记录应对的统一摘要；不生成具体操作建议、机构路径或接收方草稿，不推断接收方职责。此路径的最终审核只覆盖最新摘要及其依赖事实／分析，不要求接受不存在的建议或选择接收方。审核有效后可本地预览、复制、导出 Markdown／PDF；摘要保留上述无指引提示与合成标记，不声称已提供处置方案或完成交接。文件名使用案件编号、`summary` 和版本。

有效指引恢复后，按当前事实、角色和指引重新生成有依据的建议／草稿，并按 4.4 审核；之前事实摘要的通过状态不能代替新增输出的最终审核。

### 风险关注提示

原型只展示简单、可追溯的提醒，例如据报告远程连接仍在持续，请优先人工核实。正文使用英文，显示对应报告来源和合成指引，不自动判断现实危险等级，不执行账户、交易或设备操作。未首次核对的事实标为Reported — not yet checked；触发事实冲突或指引失效时，不继续显示原提示为有效，改为需人工核实。没有明确触发依据时不生成提示。具体有限条目随验收案例由A确定，不要求模型构建风险评分。

### 4.4 审核与导出

首次核对后仍可能有补问修改；最终审核必须覆盖最新版本。审核历史保留，但旧版本审核不能证明变化后的内容已经审核。审核阶段仅有首次核对和最终审核两种；下表规定各类变化对审核的影响。

“内容变化”包括事实值／来源／冲突、候选类型及依据、岗位权限、指引依据、建议步骤或草稿正文／接收方的变化。摘要、建议、草稿须分别标识自身版本及所依赖的内容；仅影响某一对象的变化不使无依赖的其他对象一律失效。没有实质内容变化的重复分析不产生新的审核要求。

| 操作 | 结果与审核变化 |
|---|---|
| 首次核对前更正事实或疑似类型 | 更新事实／分析；首次核对检查最新内容 |
| 首次核对后直接更改事实／类型、停止补问后主动补充，或重新分析产生内容变化 | 保留首次核对历史；员工在原核对区确认变更后才能继续后续流程。受影响摘要、建议和草稿需更新，原对应最终审核失效 |
| 正常回答当前补问产生事实／分类更新 | 保存来源并更新相关分析；不逐轮重复首次审核，最终审核统一核对最新内容。若已有最终审核，受影响输出的审核失效；已经确认的人工更正仍受保护 |
| 切换机构／岗位 | 保留事实、首次核对历史及补问计数；按新权限更新受影响建议／草稿，原对应最终审核失效 |
| 所引用指引版本或有效性变化 | 重新检查受影响摘要、建议／草稿；原对应最终审核失效，无有效依据时按 4.3 处理 |
| 接受或修改建议 | 记录员工选择；修改后同步引用该建议的摘要／草稿，变化内容需纳入最终审核。接受不等于执行 |
| 拒绝建议 | 保留拒绝理由与审核记录；该建议不得作为待执行动作进入摘要或草稿。更新引用它的摘要／草稿，原对应审核失效；拒绝不删除案件事实，重新分析不能自动撤销拒绝决定 |
| 修改统一摘要 | 摘要需重新审核；若同时更改共用案件事实，按事实变更规则处理 |
| 修改某份草稿的内容或接收方 | 该草稿需重新审核；其他未受影响草稿保持审核状态。若同时更改共用案件事实，按事实变更规则处理 |
| 仅调整排版，或重复分析结果完全相同 | 不改变内容审核有效性；排版调整仍需检查导出显示 |

员工可修改建议和摘要／草稿正文。原型保留修改前内容及Employee edited标记，修改后按对象重新审核；不新增自由文本语义判定或逐句指引匹配拦截。人工新增文字不自动标为合成指引原文或已核实事实，也不自动改写共用事实。系统生成的建议仍遵守4.3的指引和岗位边界；编辑或审核不赋予程序实际操作、发送或转介能力。

摘要／草稿生成或重算不能静默覆盖员工已修改的内容；保留人工内容并提示受影响部分，员工核对后确认更新。最终审核应显示所有未解决冲突和缺口，允许保留不确定性；不得把冲突自动当作已解决。复制或导出为已审核记录时，选定内容及其所依赖的建议（如有）必须具有有效最终审核；失效内容只能继续在页面核对。

每份草稿可单独预览、复制和下载；下载文件名包含案件编号、接收方和版本。两格式正文一致，PDF 需核对中文、表格、分页和内容完整性。审核通过不表示诈骗已确认、实际动作已执行或接收机构已经收到信息。

### 4.5 本地历史与JSON备份

支持新建、列出和打开本地合成案件，保存事实与来源、角色、问题与计数、建议决定、输出和审核版本。只在实际保存成功后显示已保存；刷新恢复的是该浏览器地址下已保存的内容，不能承诺恢复未保存修改。

| 操作或情况 | 确定结果 |
|---|---|
| 新建或切换案件时有未保存修改 | 提供Save and continue、Discard changes and continue、Cancel三个选项；取消留原案，放弃仅丢弃原案未保存变化 |
| 选择保存后继续 | 保存成功才新建／切换；失败保留原案和当前输入，不执行切换，允许重试 |
| 新建或切换时无未保存修改 | 进入所选或新建案件，事实、问答与审核不串案 |
| 下载JSON备份 | 包含本案数据及恢复所需版本，不包含模型配置和密钥；备份不等于已审核的对外交付 |
| 导入格式错误、不支持版本或引用不完整 | 清楚报错，保留当前案与已保存案；不部分覆盖 |
| 导入案件号与本地已有案相同 | 显示替换确认；取消不改变当前或已有案；确认后按正常保存结果处理 |
| 恢复／导入成功 | 检查对象依赖与审核是否仍有效，不能把模拟审核或过期审核变为有效员工审核；失败不宣称恢复成功 |

不同浏览器、地址或电脑不自动共享本地历史；使用JSON备份搬移。实际origin、大小限制和格式由运行说明及契约记录，不由成员自行修改。

## 5. 同屏双栏交互

| 信息／工作流区 | 聊天区 |
|---|---|
| 案件编号、角色、版本、阶段和轮次 | 机构／岗位选项和自由描述 |
| 分组折叠表单、来源、缺失、冲突、更正 | 每轮最多 3 个有原因的补问 |
| 疑似类型、依据、不确定性及紧急提示 | 回答、未知／无法回答、结束补问 |
| 本岗位待办、多机构建议与指引引用 | 简明说明已更新内容和下一步 |
| 两次审核、统一摘要、接收方草稿和导出 | 通过明确选择／更正确认角色变更 |

两区共用一个案件状态。补充或更正时显示受影响结果更新中或需重新审核；不得把旧分析展示成新版本已确认。聊天输入可以回答多个问题，只更新有依据的字段。字段按需展开，避免一次性呈现全部定义。左右比例、具体样式、移动端支持未固定。

## 6. 失败与恢复要求

模型超时或输出无法解析时，保留输入和已保存结果，标记本次分析失败并允许员工重试；未完成的新分析不能作为最新已审核内容。无有效指引按 4.3 的事实摘要路径继续，不靠重复请求编造指引。保存失败时保留当前页面输入并显示未保存，允许重试保存；未保存的新状态不能标为已恢复或作为已审核导出。导出失败时保留有效审核与预览，允许重试同一有效版本的导出。重试不重复计算同一轮已生成的问题，也不让部分成功的旧结果冒充完整的新分析。

请求返回时必须检查其依赖内容和是否仍为该操作的当前请求。员工已更正事实、更新角色／指引或发出较新请求后，较旧结果不得覆盖较新状态、人工内容、回答、计数或审核状态，也不得复活已失效审核；标记该结果已过期，必要时对当前内容重新分析。只有仍适用于当前内容的完整结果才能更新页面。

不能让案例输入中的命令改变系统配置或员工权限。模拟模型可用于开发，但真实模型验收与模拟结果须分开记录。

## 7. 验收计划

使用15个固定合成案例，初始叙述、补问答案和预期结果均须经内容审核。[T09可读参考](examples/WORKED_CASE.md)的有限内容已获批准，范围以data/business登记为准；其他14例在扩展验收时由A组织准备并逐项审阅。原型先跑通T09及无指引摘要，完整十五例不作为模块开发或首次集成前置；未完成时不声称全范围验收通过。任何参考正文或内容批准都不等于实际员工审核、模型效果或产品验收通过。

| 案例 | 数量 | 覆盖 |
|---|---:|---|
| T01–T05 | 5 | 五类各一个完整案例 |
| T06–T10 | 5 | 五类各一个缺失／冲突变体，覆盖补问及更新 |
| T11–T13 | 3 | 混合类型、其他类型、信息不足 |
| T14–T15 | 2 | 当前岗位权限不足、指引缺失／冲突 |

检查事实提取、分类依据、补问上限、指引引用、角色职责、接收方草稿、两次审核、版本失效、本地恢复及两种输出。角色切换、达上限、重试等可作为上述案例的交互变体。

权限、无依据事实／指引、审核失效和补问上限等关键规则在验收集内必须全部通过。报告实际通过／失败及修复复测，不预填准确率或业务改进数字。详细计划见 [tests/README.md](../../tests/README.md)。
