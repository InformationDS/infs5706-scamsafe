# ScamSafe Alliance 课程原型 PRD

## 1. 产品目标

ScamSafe 是面向 ScamSafe Alliance 成员机构一线员工的 AI 案件辅助工作台。员工输入疑似诈骗经历后，系统整理事实、发现信息缺口、提出补问，并结合演示指引生成处理建议和交接材料。

本项目交付一个能够实际运行、适合课堂展示的功能原型。成功标准是清楚展示“案件输入 → AI 处理 → 员工核对 → 有用输出”，体现机构之间如何衔接，以及员工如何参与决定。

## 2. 用户与使用场景

主要用户为 ScamSafe Alliance 成员机构内接收疑似诈骗报告的授权一线员工。原型假设使用者已获得所在机构的使用授权，通过简单选择确定角色，无需实现登录或权限管理。

联盟背景涉及银行与支付、电信、数字平台、政府诈骗报告、身份恢复与受害者支持、社区支持等机构。原型选择银行接报员工、电信接报员工两个固定角色，验证跨机构接报与交接的主要流程；其他机构作为可解释的协作背景，不声称原型已经覆盖联盟全部业务。

员工在柜台、电话或在线接报时使用工作台，将当事人的叙述输入系统，借助 AI 整理记录和准备下一步沟通。建议与交接信息按接收机构的职责区分，员工核对后通过所在机构现有流程使用；不要求成员机构共享系统或接入真实业务接口。

典型场景：当事人收到冒充银行的短信，点击链接并输入账户资料，随后发现一笔陌生扣款。银行员工需要了解事件、补充关键细节，准备给当事人的说明，并整理电信机构可接收的短信相关交接记录。

工作台用于员工接报过程中的辅助整理；员工根据系统结果继续沟通和决定下一步。原型展示本地草稿，不连接真实银行、电信系统或实际发送转介。

## 3. 原型范围

| 纳入范围 | 不纳入范围 |
|---|---|
| 两个固定机构角色及对应职责说明 | 账号体系、权限管理、多人协作 |
| 自由文本输入、AI 事实提取和疑似类型分析 | 附件解析、OCR、真实案件数据库 |
| 案件内问答、缺失提示及一轮有明确数量的补问 | 开放领域聊天、复杂问题调度与冲突历史 |
| 有原文依据的紧急性／脆弱性线索 | 风险评分、自动处置或专业诊断 |
| 少量团队审阅的虚构指引和跨机构建议 | 指引审批平台、版本管理和规则引擎 |
| 可编辑摘要、当事人说明和交接草稿 | 自动联系机构、发送消息或执行交易操作 |
| 页面预览、复制、Markdown 下载 | 多格式导出、案件导入迁移及审计系统 |
| 单案操作、重新开始、基础错误重试 | 多案件历史、生产部署及安全治理建设 |

界面和生成材料使用英文，案件输入支持中文和英文。演示使用虚构人物、机构和事件。

## 4. 核心用户流程

1. **选择角色**：选择银行或电信员工，查看本角色职责。
2. **输入案件**：在右侧输入叙述或载入一个演示案例，提交后 AI 整理事实，在左侧展示摘要、疑似类型及依据。
3. **对话核对与补充**：员工主要在右侧回答追问、主动补充、更正或询问已有数据和判断依据；左侧随对话持续更新，也允许直接编辑事实。
4. **明确数量后追问**：确有关键缺口时，AI 先说明本轮问题总数、涉及的事项及可以跳过，再逐题提问并标明第几问／共几问。员工可以回答多个问题、中途反问、表示不确定或提前结束。
5. **查看建议与生成材料**：信息足够或员工选择继续时，AI 提示可查看建议或生成材料，并提供快捷操作；根据当前事实、角色和演示指引准备对应内容。
6. **确认与使用**：员工在左侧查看、编辑并确认材料，随后复制或下载；右侧仍可查询、补充或更正案件信息。

上述流程是常见使用路径，不是必须依次完成的表单关卡。用户可以围绕当前案件随时提问或补充，不必选择问题编号或切换到独立答题页面。AI 每次响应员工发言后都应明确说明下一步应该或可以做什么。

开始新案时清空当前案件；有内容时先提示确认。切换角色按新案开始，界面提前说明会清空当前内容。

## 5. 功能要求与验收

| ID | 功能 | 验收标准 |
|---|---|---|
| FR-01 | 角色选择 | 提供银行、电信两个角色；显示当前角色及职责，建议能够体现其差异 |
| FR-02 | 案件输入与实际 AI 分析 | 输入文本后实际调用模型，显示处理中状态，并根据输入生成结果；载入示例只填入文本，仍需执行分析 |
| FR-03 | 结构化事实 | 按业务分组显示已知信息和关键缺口；未知显示为 Unknown，不填成否或零；员工可直接编辑，也可通过对话更正；两种方式更新同一案件事实 |
| FR-04 | 疑似类型及关注线索 | 显示候选类型、简短理由和相关叙述依据；标出报告中明确出现的紧急性、脆弱性或人工介入线索；没有依据时不添加 |
| FR-05 | 有数量和进度的补问 | 根据当前案件准备一轮、最多三个关键问题；提问前先说明总数及目的，默认逐题展示“第 i／N 问”；支持一次回答多个问题、反问、不知道、跳过和结束，正确更新剩余问题；没有必要时不发起补问 |
| FR-06 | 指引与处理建议 | 根据当前事实和角色提供建议，显示所用演示指引名称或编号；明确本机构事项、其他机构事项和需要人工判断的事项 |
| FR-07 | 输出材料 | 生成案件摘要、给当事人的说明，以及适用的接收机构交接草稿；内容反映员工更正和补问结果 |
| FR-08 | 编辑与确认 | 员工可编辑生成材料，最终确认后复制或下载；再次编辑时回到待确认状态 |
| FR-09 | 预览与下载 | 在页面查看完整材料；可独立复制或下载所选材料的 Markdown 文件，内容与页面一致 |
| FR-10 | 失败重试 | 模型失败时保留当前输入，显示清楚的错误和重试入口；处理中禁用重复提交 |
| FR-11 | 案件对话与事实同步 | 对话支持叙述、回答、主动补充、更正、查询已有数据及解释分析依据；明确更正才更新对应事实，查询或反问不自动改值；分析区展示最新事实，不重复设置回答表单 |
| FR-12 | 每次响应提示下一步 | 每次响应员工发言，先回答或回应，再说明实际更新或仍不明确的信息，最后给出符合当前情境的下一步；需要时提供继续回答、保留未知、查看建议或生成材料等快捷操作 |

### 5.1 案件信息

采用约 20 项核心信息，按相关性展示，无需员工填写完整表单：

| 分组 | 信息 |
|---|---|
| 接报背景 | 当事人叙述、员工机构角色 |
| 事件经过 | 接触渠道、接触时间、对方声称身份、主要行为 |
| 资金情况 | 涉及金额、币种、交易状态、涉及机构 |
| 资料与账户 | 泄露资料类别、受影响服务、发现的异常 |
| 当前情况 | 是否仍在联系、已采取的措施、已联系的机构 |
| 材料与求助 | 可提供的证据说明、紧急性线索、脆弱性或支持需求、关键缺口或矛盾 |

这些信息用于整理叙述，不是必填清单。金额和状态保留报告中的含义，不把陌生扣款直接写成已确认损失。只记录资料类别，无需输入密码或验证码本身。原型以单次主要事件、单笔主要交易为演示范围；额外事件可保留在叙述与备注中。

事实卡片提供查看相关原文的入口。信息冲突时显示相互矛盾的内容，让员工编辑或保留待确认；无需逐次修改历史。员工已更正的值作为后续生成材料的依据。

### 5.2 类型与补问

候选类型覆盖投资、付款重定向、恋爱、网络钓鱼和远程访问，允许多个标签，以及其他／信息不足。类型用于帮助理解案件，不作为必须完成的五选一表单。

补问由模型根据当前案件生成，程序负责按约定的数据结构呈现。补问优先关注当前是否仍在发生、资金或账户情况，以及影响交接的关键缺口，不为填满所有字段而提问。

本轮最多三个问题，开始追问前先确定并告知实际数量及各问题涉及的事项，然后默认一次问一个。例如（产品中使用英文）：

> 为了整理下一步建议，我有 3 个问题需要确认，涉及交易状态、是否仍在联系，以及是否联系过银行。你可以随时回答不知道或跳过。第 1／3 问：这笔 AUD 200 的交易目前是待处理还是已完成？

| 用户发言或情况 | AI 的回应与进度处理 |
|---|---|
| 回答当前问题 | 回应答案，说明更新的信息，左侧同步；再提出下一道未处理问题并标明序号／总数 |
| 一次回答多个问题 | 将有明确依据的回答关联到对应问题，更新事实与进度；不重复询问已回答的问题 |
| 不知道或不确定 | 保留未知或不确定；当前问题标为已处理但未明确，不猜填事实，再提示下一问或可继续的操作 |
| 跳过或结束补问 | 跳过当前问题，或将剩余问题标为跳过并结束；保留缺口，提示可补充信息、查看建议或生成材料 |
| 中途反问已有数据或判断理由 | 先根据记录回答并说明依据；不将反问当作补问答案，不推进问题进度；再提示当前待答问题 |
| 问题因新信息不再适用 | 说明原因，标为不适用并跳过；保留可理解的进度，不继续要求作答 |
| 确需调整或增加问题 | 先解释原因、调整后的总数和剩余数量，再继续；不悄悄追加，不突破本轮三个问题的范围，超出范围的缺口保留供员工核实 |
| 本轮完成 | 总结已明确和仍未知的信息，说明可继续补充、查看建议或生成材料；不强制开启新一轮 |

用户可以在补问结束后主动补充信息，也可以询问案件情况，无需重新开启补问流程。问题和回答入口统一在右侧对话区；左侧仅展示进度、事实及缺口，不要求用户选择 Question 1／2／3 后才能回答。

### 5.3 演示指引与机构路径

团队准备一小组虚构指引，覆盖银行接报、电信接报、跨机构交接和人工支持。每条指引只需包含编号、适用场景、相关机构、建议事项和人工介入条件。正式演示前由团队检查其内容。

AI 结合案件事实和这些指引组织建议。每项建议显示负责机构、建议内容、理由及指引引用；可用“优先处理”和“后续处理”区分顺序。需要同时联系多个机构时，说明可以并行开展。

找不到适用指引或信息不足时，明确说明需要员工或专人判断，仍生成事实摘要和待确认事项；不强行为每个机构生成建议或交接材料。

### 5.4 输出材料

| 材料 | 必须包含 |
|---|---|
| 案件摘要 | 事件经过、主要事实、疑似类型、已采取措施、尚不明确的信息 |
| 给当事人的说明 | 易懂的事件说明、指引支持的下一步、需要补充的材料或人工支持 |
| 机构交接草稿 | 接收机构、交接原因、与该机构相关的事实、待确认事项和请求协助内容 |

材料将已明确信息与剩余缺口分开；普通查询、界面操作命令及对话原文不直接拼入业务摘要。所有材料标注为课程演示的虚构案件。员工确认表示已阅读并准备使用草稿，不表示已经联系机构或完成处置。

事实发生变化后保留已有材料及员工编辑，将材料标为需要更新，撤销确认并暂停复制／导出；不得因编辑事实直接清空材料。页面提示重新生成材料并重新确认。重新生成前说明会替换现有材料，员工可以取消；不要求分别维护每份材料的审核版本或依赖关系。

## 6. 页面与易用性

采用同屏双栏工作台，两区共用同一案件内容：

| 分析区（左侧） | 对话区（右侧） |
|---|---|
| 展示并核对分组事实、疑似类型和依据 | 输入原始案件叙述 |
| 展示补问进度、更新后的事实和剩余缺口 | 接收带数量和进度的追问，回答、反问、不知道、跳过或结束 |
| 直接编辑事实 | 查询案件数据及判断依据、主动补充或明确更正事实 |
| 查看建议、编辑材料、确认和导出 | 简短说明更新结果及下一步 |

右侧是用户的主要操作入口，持续支持案件输入、查询、解释、补充与更正。员工可以问“目前记录的金额是多少”“为什么认为是网络钓鱼”，也可以说“金额不是 2000，是 200”。左侧是 AI 基于当前案件整理出的结果面板，供员工查看和核对。

必须区分查询、明确更正和不确定表达：“金额是 200 吗？”是在询问，不直接把金额改成 200；“金额不是 2000，是 200”是明确更正，可以更新；“我不确定是否已完成交易”保留为不确定。缺乏依据时，AI 说明当前无法确定，并指出可以向谁或通过什么信息确认，不将查询本身当成事实。

AI 每次响应员工发言均包含与本次内容相关的三部分：回应问题或陈述；说明实际更新的事实或仍未明确的信息（无变化时无需声称已更新）；明确下一步应该或可以做什么。下一步随当前情况变化，可是下一道追问、核对某个数据、保留未知、查看建议或生成材料，不机械重复固定提示。

事实更新后，分析区立即展示变化，对话区说明更新内容；已有材料提示需要重新生成，并在员工确认替换后更新。更正后的事实不因重新读取初始叙述而自动还原。

- 顶部显示当前角色、案件状态和重新开始入口，不提供五阶段流程导航。角色选择只在新案初始化时出现。
- 左侧提供可自由切换的三个结果标签：案件概览、处理建议、输出材料。案件概览持续展示最新事实、疑似类型和缺口；处理建议展示机构职责与依据；输出材料用于编辑、确认、复制和下载。
- 右侧显示当前追问及进度、每次回应的下一步和快捷操作；追问不作为独立页面或导航标签。切换左侧结果标签不改变对话、追问进度或案件事实。
- 未生成建议或材料时，结果区域说明当前状态及如何通过对话操作获取内容，不要求先完成全部追问。
- 事实按组呈现，只展开与案件相关的信息，缺口和矛盾容易找到。
- 对话回复按情境提供快捷操作，例如查看建议、生成材料或结束补问；左侧保留必要的编辑、确认和导出操作。
- 桌面演示时，输入区和当前操作保持容易访问；内容较长时在面板内滚动。
- 结果摘要先于详细字段，来源和指引可以按需展开。
- UUID、字段代码、模型请求日志和测试开关不出现在主要业务界面。

不要求移动端适配、复杂动画或完整设计系统；桌面主流程需清晰可读、操作顺畅。

## 7. AI 实现与运行要求

采用文本大模型配合固定演示指引，完成事实提取、补问、建议及材料生成。指引规模较小时可直接提供给模型，不要求向量数据库、多智能体或外部工具调用。

接通一种可用模型服务即可。模型地址、名称和密钥可以通过运行配置提供，无需开发通用 API 设置平台。交付中包含提示词、演示指引和必要配置说明，让团队能够解释输入如何转为输出。

系统在单台电脑运行，单次处理一个案件。开发可使用模拟结果；用于证明 AI 功能的演示需有实际模型处理，不能仅切换预写结果。记录实际采用的模型与配置，以及演示验证结果。

## 8. 功能验收

准备三个固定虚构案例，记录输入、观察结果及通过／失败：

| 案例 | 检查重点 |
|---|---|
| 信息较完整的跨机构案件 | 能提取事实，显示类型和指引，生成银行／电信相关建议及有用材料 |
| 存在缺口或矛盾的案件 | 能提出关键补问，接受更正与不知道，材料反映更新后的内容 |
| 信息不足或需要人工支持的案件 | 能说明局限和人工介入需要，仍输出可用事实摘要，不编造确定结论 |

对话交互需实际检查以下情境：

| 检查项 | 预期表现 |
|---|---|
| 开始补问和逐题回答 | 先告知实际总数，再出现第 1／N 问；每次回答后反馈更新及下一步，进度正确 |
| 一次回答多个问题 | 更新对应事实和问题状态，下一次只问仍需处理的问题 |
| 不知道、跳过、提前结束 | 保留缺口，说明下一步，不强迫填写全部信息 |
| 查询“目前金额是多少”及“为什么认为是网络钓鱼” | 依据案件记录回答，不改变事实或补问进度，回答后提供下一步 |
| 询问“金额是 200 吗”与明确更正“金额不是 2000，是 200” | 前者不改值，后者更新；分析区和最终材料采用更正后的事实 |
| 问题不适用或需要调整 | 解释原因和数量变化，不重复已处理问题，不静默追加 |
| 每次响应与材料生成 | 每次回应都有符合当前情境的下一步，员工可主要通过右侧完成信息收集及触发材料生成 |

同时确认分析区和最终材料反映同一份最新事实。

另外检查一次模型失败重试、材料编辑确认、复制下载，以及重新开始。银行和电信两个角色都需实际运行至少一个案例，验证结果体现角色职责。

验收通过表示所记录案例中的演示流程可用，不代表覆盖所有诈骗情境。功能完成以实际运行结果为准。

## 9. 案例需求对应

| ScamSafe Alliance 案例要求 | 本产品的对应能力 |
|---|---|
| 收集并整理相关信息 | 自由叙述输入、分组事实和员工核对 |
| 发现缺失、冲突或不确定信息 | 缺口提示、有数量和进度的补问、未知及更正处理 |
| 识别紧急性或脆弱性线索 | 展示报告中有依据的关注项和支持需求 |
| 获取获认可的诈骗应对指引 | 使用团队审阅的有限虚构指引，显示引用依据 |
| 支持选择适当处理路径 | 区分本机构、其他机构和人工介入事项，说明理由与顺序 |
| 准备给受影响人的指导 | 生成可由员工编辑确认的当事人说明 |
| 识别专人或人工介入需要 | 信息不足、需要支持或超出本机构职责时提示人工评估 |
| 准备一致的案件记录与机构交接 | 使用同一案件事实生成摘要及相关接收机构草稿 |

双栏布局、两个演示角色、一轮最多三个问题、三个验收案例和 Markdown 下载是本原型的范围与交互选择，不是作业指定的界面、数量或格式。AI 的案件内问答服务于上述接报与交接任务。
