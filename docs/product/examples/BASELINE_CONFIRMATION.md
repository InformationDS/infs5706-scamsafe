## 3. 两条路径的门槛

| 路径 | 必要条件 | 允许的业务输出与审核 |
|---|---|---|
| 无有效指引 | 先有实际有效岗位；测试时显式不加载有效 EX-G 配置，不能支持具体建议 | 显示 `Insufficient approved guidance; human review required`；可提取事实、候选分类、补问或主动结束，只生成统一事实摘要；不生成 REC-01–03、机构路径或接收方稿。最终审核覆盖最新摘要及依赖事实／分析，审核有效且状态已保存后才可复制／导出 |
| 有有效指引 | 实际有效岗位及职责配置；对应指引获团队审核、当前有效、条件满足且符合权限；用于验收的案例／预期另获批准 | 仅生成有依据的建议、摘要及相关接收方稿；依对象绑定案例及依赖版本，完成有效最终审核后输出。事实摘要旧审核不能代替新增建议／草稿审核 |

本次已批准有效岗位、有限指引及两路径参考预期。data/business/ 提供实际批准包和校验入口；现有 data/fixtures/ 仍是 pending 的模拟程序数据，不能自动升级为已批准案件或真实审核快照。完整指引匹配、建议与拒绝传播和正式业务端到端验收仍待实现。

## 4. 独立变体与共同规则

| 独立变体 | 起点与区别 |
|---|---|
| 主线拒绝建议 | WORKED_CASE 第 5 节在最终审核前拒绝 REC-03；电信稿更新后仍待审核 |
| 审核后拒绝建议 | T09 预期稿“拒绝建议”从两稿已最终审核开始；拒绝 REC-03 后引用该动作的电信稿需重审；银行稿不因无依赖动作失效 |
| 主动结束但尚有未答项 | T09 预期稿“主动结束”是另一个起点；未答项变为已跳过。主线已把 Q2/Q3 标未知，不能把这两种历史混为一条 |
| 结束后补充 Q3 | WORKED_CASE 第 3、7 节：更新原问与 E08 / TX-01，保留原未知历史；不新增问数、不恢复补问；变更需确认并更新受影响输出审核 |
| 审核后金额改 250 | 从有效最终审核的 200 版本独立开始；两稿均依赖金额，均需重审 |
| 角色切换、刷新、旧请求晚返回 | 分别使用声明清楚的初始状态；第二岗位配置尚未建立，角色切换行为预期获批不等于该变体可直接运行 |

共同遵循 PRD 4.1–4.4、6：未知不等于否或 0；人工更正及正文不能被模型静默覆盖；补问首次成功展示且保存才计数，部分回答不增轮次；同案上限 3 轮 9 问，停止后不新增补问；最终审核按对象依赖失效；接受不等于执行，审核不等于外部核实或已送达；旧请求不能覆盖较新状态或复活审核；模拟、真实模型结果、内容审核和运行验证分别记录。

案件版本使用实际整数；WORKED_CASE 的 V1/V2/VF 只是讲解标签。输出正文及文件名必须使用具体有效版本，不能留下版本占位。PDF 的内容、中文、表格和分页需实际检查，结构校验不能代替视觉验收。
